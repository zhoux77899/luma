# Infrared transmits a pulse frame and REMOTE owns encoding

Cardputer ADV can transmit infrared and cannot receive it. A protocol enum on the Core contract would grow every time a television family is added, and a receive API would describe hardware the board does not have. Infrared accepts one Frame, a carrier plus mark and space durations, and has no receive call. REMOTE encodes NEC, Samsung, Sony, RC6, Panasonic, and a custom description stored on that Remote.

The custom description is wider than the original "type a hex code" wording. A fixed hex field cannot say what a pulse-width frame or a Manchester frame is. The description stays on the Remote, so two Remotes do not share one edited protocol.

The REMOTE face keeps the Header and drops the Footer. Six keys plus a brand mark do not fit in the 88px band under a Footer, and the keys fire from the keyboard rather than from a focused row. This is the exception to ADR-0006's "Apps keep Header plus Footer".

Brand marks come from redistributable Commons SVGs. Near-black and near-white pixels follow Theme preference so a black wordmark stays visible on Kuro and on Gofun. Chromatic brand color is kept, which is why those seven bitmaps are allowed outside the DESIGN.md palette.
